# SHIFT --- 最小可玩 Demo 设计说明

**版本：** v0.2\
**项目主题：** Game Off 2026 --- SHIFT\
**文档用途：** 第一版可玩战斗 Demo 的设计依据，供开发者和 AI Agent
阅读。

------------------------------------------------------------------------

## 1. 游戏概念

SHIFT 是一款以单一按键 **Shift** 为核心操作的简洁对决游戏。

玩家与 Boss
在画面左右两侧正面对峙。双方持有相同顺序的三种武器，并在持续推进的时间轴中决定是否切换武器。每个时间单位结束时，双方根据当时持有的武器自动执行对应行为，并结算伤害。

第一版 Demo 的重点是验证：

-   仅使用一个按键切换武器，能否形成有趣的战斗决策；
-   剑、盾牌、重剑之间的基础交互是否成立；
-   双方同时行动、按时间单位结算的战斗循环是否易于理解。

第一版不以完整 RPG
或剧情体验为目标，而是优先完成一个能够从开始运行到胜负结算的最小战斗原型。

## 2. 核心设计原则

1.  **唯一操作按键是 Shift。** 玩家不需要单独的攻击键、防御键或确认键。
2.  **切换武器就是主要决策。**
    玩家决定保持当前武器，还是切换到下一把武器。
3.  **时间持续推进。** 战斗由连续的倒计时和离散的时间单位构成。
4.  **双方共用基础规则。** 玩家和 Boss
    使用相同的武器顺序、切换限制、重剑蓄势规则和伤害结算规则。
5.  **先做简单、可运行的版本。** 第一版不加入武器组合、复杂 Boss
    AI、剧情、成长系统或多阶段战斗。

## 3. 战斗画面与视觉方向

### 3.1 画面布局

-   玩家与 Boss 采用**左右对峙**的构图，而不是前后纵深站位。
-   玩家位于画面左侧，Boss 位于画面右侧。
-   双方生命条位于画面上方。
-   中央区域用于展示双方角色和武器动作。
-   时间轴位于画面下方，绿色游标沿时间轴逐格移动。
-   倒计时数字显示当前时间单位剩余的秒数。

画面应保持紧凑，不要让角色过分靠近屏幕左右边缘。整体视觉方向是简洁、低分辨率、有限调色板的复古像素风格。

**逻辑分辨率尚未最终确定。** 之前讨论过
4:3、较紧凑的画幅，但具体宽高需要根据现有示例图和实际布局在 Godot
中确认，不应由开发 Agent 擅自定死。

### 3.2 美术与素材原则

-   正式视觉素材使用独立 PNG 文件。
-   不要用 GDScript 的 `draw_rect()`、`draw_circle()`、`_draw()`
    等方式绘制角色、武器或正式 UI 来替代 PNG。
-   可以使用 Godot 节点控制 PNG
    的位置、缩放、透明度、显示区域和动画播放。
-   像素素材应保持硬边缘，不进行平滑缩放或抗锯齿处理。
-   原始美术工程文件可以与对应 PNG 放在一起，不要求单独建立 `art_source`
    目录。
-   第一版优先复用已经制作的素材，不为了丰富画面而继续扩充美术工作量。

### 3.3 当前已有或已规划的素材

角色动作目前包括：

  动作         建议英文名称        建议文件名
  ------------ ------------------- -------------------------
  普通剑攻击   Sword Attack        `sword_attack.png`
  盾牌防御     Shield Guard        `shield_guard.png`
  重剑蓄势     Greatsword Windup   `greatsword_windup.png`
  重剑攻击     Greatsword Attack   `greatsword_attack.png`

玩家和 Boss 可以使用相同的动作结构。Boss
的临时版本可以通过对玩家素材进行调色处理得到；处理时应保留 PNG
尺寸、透明通道和像素轮廓，不要重新绘制或缩放。

UI 素材建议命名：

  用途             文件名
  ---------------- ------------------------
  生命条背景       `health_bar_bg.png`
  生命条填充       `health_bar_fill.png`
  时间轴           `timeline_bar.png`
  时间游标         `timeline_cursor.png`
  倒计时数字图集   `countdown_digits.png`

倒计时数字可以集中放在一张图集中，由程序按需要选取对应数字显示。时间轴上的格子分隔可以由
Godot 节点或布局实现，不必把每一格都画进同一张图片。

## 4. 游戏启动与开始方式

-   游戏启动后直接显示战斗界面。
-   初始状态为等待开始，时间暂停，倒计时不推进。
-   玩家第一次按下 Shift 时，游戏正式开始。
-   **开始游戏的这一次 Shift 不触发武器切换。**
-   玩家初始持有普通剑。
-   Boss
    的初始武器建议也设为普通剑，以便双方从相同基础状态开始；这一点如需不同，应在实现前明确修改。

开始之后，游戏进入循环时间单位。

## 5. 时间系统

### 5.1 时间单位

-   一个时间单位持续 **3 秒**。
-   每个时间单位内，倒计时依次显示 `3`、`2`、`1`。
-   倒计时结束时，该时间单位结束。
-   时间游标向右移动一个格子。
-   双方在该时间单位结束时，根据本回合最终持有的武器执行行为并结算伤害。
-   如果没有分出胜负，进入下一个时间单位，倒计时重新开始。

### 5.2 每个时间单位内的 Shift 输入

-   每个时间单位内，玩家可以选择不按 Shift，或按一次 Shift。
-   不按 Shift：保持当前武器。
-   按一次 Shift：沿固定武器顺序切换到下一把武器。
-   每个时间单位最多只允许一次有效切换。
-   切换武器不消耗时间，也不会让倒计时暂停。
-   同一时间单位内再次按下 Shift，不产生额外切换。

玩家不需要另外按键选择攻击或防御。当前武器决定时间单位结束时执行的行为。

## 6. 武器系统

### 6.1 武器顺序

双方使用相同的循环顺序：

**普通剑 → 盾牌 → 重剑 → 普通剑**

每次有效 Shift
只向后切换一把武器。第一版不提供自由选择任意武器，也不允许一次跳过多把武器。

### 6.2 普通剑（Sword）

-   普通剑是基础进攻武器。
-   持有普通剑时，角色处于非防御状态。
-   普通剑攻击正常命中时，造成 **2 点伤害**。
-   两名角色都持有普通剑时，双方各受到 **2 点伤害**。

### 6.3 盾牌（Shield）

-   盾牌是防御武器。
-   当前持有盾牌即视为处于防御状态。
-   普通剑攻击盾牌时：
    -   盾牌方不受到伤害；
    -   持剑攻击者受到 **1 点反伤**。
-   盾牌面对重剑攻击时，不能完全防住重剑：
    -   盾牌方受到 **3 点伤害**；
    -   重剑攻击者不因这次攻击受到反伤。

### 6.4 重剑（Greatsword）

重剑采用两阶段机制：**蓄势（Windup）→ 攻击（Attack）**。

#### 第一阶段：进入重剑并蓄势

-   角色通过 Shift 切换到重剑。
-   该时间单位播放重剑蓄势动作。
-   这一回合不发动重剑攻击。
-   蓄势期间角色属于**非防御状态**，不能获得盾牌的防御效果。
-   因此，蓄势期间可能受到对方攻击。

#### 第二阶段：决定继续蓄势还是切换离开

进入重剑后的下一个时间单位，角色可以作出选择：

-   **不按 Shift，继续持有重剑：** 完成蓄势，发动重剑攻击。
-   **按 Shift 切换到下一把武器：**
    放弃本次重剑蓄势，不发动重剑攻击，并按照新武器执行该回合行为。

例如，角色从重剑切换到普通剑后，该回合执行普通剑攻击，而不是重剑攻击。

重剑攻击的伤害：

-   攻击处于防御状态、持有盾牌的对手：造成 **3 点伤害**。
-   攻击处于非防御状态的对手：造成 **5 点伤害**。

重剑蓄势和攻击是两个不同的时间阶段，不能在刚切换到重剑的同一回合立即造成重剑伤害。

## 7. 防御状态的定义

第一版采用简单的二分定义：

-   **防御状态：** 当前持有盾牌。
-   **非防御状态：** 当前持有普通剑，或处于重剑蓄势/持有重剑的状态。

因此，普通剑和重剑都不能获得盾牌的防御效果。重剑蓄势期间尤其容易受到攻击。

## 8. 生命值与伤害

-   玩家初始生命值：**7 点**。
-   Boss 初始生命值：**7 点**。
-   生命条素材的逻辑尺寸为 **14 × 1 像素**。
-   每 **2 个像素**代表 **1 点生命值**。
-   因此，生命条总共显示 7 格生命。

伤害发生后，按实际伤害点数减少生命值。生命值不能低于 0。

### 8.1 已明确的交互

  一方当前武器/状态   另一方当前武器/状态   已确定的结果
  ------------------- --------------------- --------------------------------------
  普通剑              普通剑                双方各受到 2 点伤害
  盾牌                普通剑攻击            盾牌方受到 0 点；持剑方受到 1 点反伤
  重剑攻击            盾牌                  盾牌方受到 3 点伤害；重剑方不受反伤
  重剑攻击            非防御状态            非防御方受到 5 点伤害

伤害结算应根据双方在本时间单位结束时的武器状态进行。玩家与 Boss
的行为属于同一时间单位内的交锋，不应简单地让某一方先执行、另一方因此失去本回合行动机会。

## 9. Boss AI

第一版 Boss AI 使用非常简单的随机策略，不设计复杂行为树或学习机制。

-   Boss 使用与玩家相同的武器顺序：普通剑 → 盾牌 → 重剑。
-   Boss 遵循每个时间单位最多切换一次的规则。
-   每个时间单位，Boss 独立进行一次随机判断：
    -   **50% 概率按 Shift：** 切换到下一把武器；
    -   **50% 概率不按 Shift：** 保持当前武器。
-   Boss 同样遵循重剑蓄势和下一回合继续攻击/切换离开的规则。
-   第一版不要求 Boss 根据玩家血量、武器或历史行为调整策略。

随机判断应在每个时间单位进行一次，并且该时间单位内保持决定不变，不能在倒计时的每一帧反复重新抽取随机结果。

## 10. 胜负与时间轴结束

-   任意一方生命值降至 0，战斗结束。
-   玩家生命值降至 0：玩家失败。
-   Boss 生命值降至 0：玩家胜利。
-   时间游标走到时间轴末端时，如果双方仍然没有分出胜负，则判定为平局。
-   时间轴末端的格子数量以当前 UI
    示例素材/布局为准；若尚未确定，应在实现前指定具体格数。

如果双方在同一个时间单位结算后都降至
0，应判定为平局。双方伤害应先完成同一时间单位的结算，再统一检查胜负，避免因代码执行先后顺序导致结果偏向某一方。

## 11. 第一版 Demo 的实现范围

### 必须实现

1.  显示战斗界面，初始暂停等待。
2.  第一次按 Shift 开始游戏，且不切换武器。
3.  玩家与 Boss 的初始生命值均为 7。
4.  显示 3、2、1 倒计时。
5.  每 3 秒结束一个时间单位，时间游标移动一格。
6.  玩家每个时间单位最多切换一次武器。
7.  武器按普通剑、盾牌、重剑的固定顺序循环。
8.  实现普通剑、盾牌、重剑的已确定交互。
9.  实现重剑蓄势与下一回合攻击/取消机制。
10. Boss 使用 50% 切换、50% 保持的随机策略。
11. 更新双方生命条。
12. 实现胜利、失败和平局判定。

### 暂时不实现

-   武器组合或自由排列；
-   复杂 Boss AI；
-   多个 Boss 或多场战斗；
-   武器获取、成长和装备系统；
-   剧情、对话和过场；
-   复杂音效、音乐和特效；
-   复杂接触、碰撞或受击动画；
-   开始菜单、设置菜单和其他非必要界面。

## 12. 开发时需要避免的做法

-   不要擅自增加攻击键、防御键、确认键或其他操作。
-   不要把 Shift 切换设计成消耗一个时间单位。
-   不要允许玩家在同一时间单位内多次切换。
-   不要让重剑在刚切换进去的同一回合立即攻击。
-   不要把重剑蓄势误认为防御状态。
-   不要给 Boss 编写复杂 AI；第一版只需要每回合一次 50/50 随机判断。
-   不要用代码绘制正式角色、武器或 UI 美术来替代 PNG。
-   不要为了扩展性提前增加当前 Demo 不需要的系统。

## 13. 尚待确认的规则细节

以下项目目前没有被完整定义。开发时不要自行把猜测当成正式规则，建议先采用最简单、可调整的实现，并将这些项目单独标注：

1.  **重剑攻击之后的状态：**
    攻击完成后是否仍然持有重剑？如果下一回合继续不切换，是再次攻击，还是必须重新蓄势？
2.  **未明确的武器组合：**
    例如盾牌对盾牌、重剑对重剑、普通剑对重剑的具体伤害和交互，需要进一步明确。已明确的规则不得被这些待定项覆盖。
3.  **同回合伤害：**
    设计意图是双方在同一时间单位内同时交锋、独立结算伤害；若双方同时归零，则平局。
4.  **Boss 初始武器：**
    建议与玩家一样初始持有普通剑，但应在实现配置中明确。
5.  **时间轴格数：**
    需要根据现有示例图确定具体格数，以决定整场战斗的最长时间。
6.  **倒计时显示时序：**
    需要在实现时明确每个数字的显示时长与游标移动时刻，确保一个时间单位总长为
    3 秒。

## 14. 第一版 Demo 的验收标准

当以下流程能够完整运行，就可以认为第一版 Demo 已经完成：

1.  启动游戏，画面停在初始战斗界面。
2.  玩家按一次 Shift，游戏开始，玩家仍然持有普通剑。
3.  倒计时显示 3、2、1。
4.  玩家可以在倒计时期间选择按一次或不按 Shift。
5.  Boss 同时进行自己的随机切换决策。
6.  时间单位结束，游标移动一格，双方根据最终武器状态执行动作。
7.  双方生命值按规则变化。
8.  下一时间单位继续循环。
9.  一方生命值归零时显示胜负；时间轴走完仍未分胜负时显示平局。

**第一版的成功标准不是内容丰富，而是仅靠一个 Shift
键、三种武器和一条时间轴，就能形成一场完整、可重复游玩的对决。**
